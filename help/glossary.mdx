Use this glossary when you see an unfamiliar word in the app or another guide.

## People and roles

<AccordionGroup>
  <Accordion title="Admin">
    A user who manages Projects, Project Types, tasks, forms, team accounts, assignments, submissions, approvals, verifications, SOS incidents, analytics, and exports across the organisation. An Admin cannot create or manage other Admins and cannot archive Projects.
  </Accordion>

  <Accordion title="Collector">
    The person who created a field record. An Enumerator, Supervisor, Admin, or Super Admin can be a collector when they have an active task assignment.
  </Accordion>

  <Accordion title="Enumerator">
    A field user who collects records for assigned tasks. Enumerators see their assigned work and their own submissions.
  </Accordion>

  <Accordion title="Super Admin">
    The protected system-owner account. The Super Admin has all Admin abilities and can also create Admins, manage Admin accounts, access Settings, and archive Projects or Project Types.
  </Accordion>

  <Accordion title="Supervisor">
    A user who oversees work within assigned Projects, approves permitted Enumerator submissions, reviews verifications, monitors analytics, and responds to SOS alerts from direct reports. A Supervisor needs a direct task assignment to collect a record.
  </Accordion>
</AccordionGroup>

## Projects and assignments

<AccordionGroup>
  <Accordion title="Assignment">
    Permission for one team member to work on one task in a client Project. An assignment may be open-ended or have an end date. It can be removed and later reinstated.
  </Accordion>

  <Accordion title="Client Project">
    A specific client engagement or work location. It contains attached Project Types and selected tasks. For example, “Ajah Meter Audit.”
  </Accordion>

  <Accordion title="Project Type">
    A reusable template containing related tasks and forms. The same Project Type can be attached to several client Projects.
  </Accordion>

  <Accordion title="Task">
    A separately assignable unit of fieldwork inside a Project Type. Each active task uses one active published form.
  </Accordion>

  <Accordion title="Variant">
    A category within a task, such as an asset or equipment type. A variant is descriptive task information and is not a separate assignment.
  </Accordion>
</AccordionGroup>

## Forms and fields

<AccordionGroup>
  <Accordion title="Automatic field">
    A read-only value generated by the app when a record is saved. The collector does not type it manually.
  </Accordion>

  <Accordion title="Conditional field">
    A question shown only when another answer meets a rule. For example, a description may appear only after the user selects “No.”
  </Accordion>

  <Accordion title="Field">
    One question or data entry item in a form, such as a text box, number, choice, GPS location, or photo.
  </Accordion>

  <Accordion title="Form">
    The versioned set of stages and questions used to collect a task record.
  </Accordion>

  <Accordion title="Form version">
    A numbered snapshot of a form. Published versions cannot be edited, and each submission keeps the exact version used during collection.
  </Accordion>

  <Accordion title="Repeatable group">
    A set of questions that can be completed more than once. It is useful for recording several similar items in one submission.
  </Accordion>

  <Accordion title="Required field">
    A question that must be completed before the record can be submitted. Required fields are normally marked with an asterisk.
  </Accordion>

  <Accordion title="Stable key">
    The internal name used to store a field's answer. Labels can be written for users, but stable keys preserve the connection to saved data and should not be changed carelessly.
  </Accordion>

  <Accordion title="Stage">
    One section of a longer form. Stages divide data collection into manageable steps.
  </Accordion>
</AccordionGroup>

## Records and evidence

<AccordionGroup>
  <Accordion title="Evidence">
    Supporting information attached to a record, especially photos, capture times, GPS coordinates, and recorded addresses.
  </Accordion>

  <Accordion title="GPS">
    Global Positioning System coordinates showing latitude and longitude. The app may capture these from the user's device when permission is granted.
  </Accordion>

  <Accordion title="Reference">
    A short, readable identifier displayed for a submission. It is different from the submission UUID used by some administrative workflows.
  </Accordion>

  <Accordion title="Submission">
    A field record tied to a client Project, task, collector, assignment, and exact form version. A submission begins as a draft and becomes final when submitted.
  </Accordion>

  <Accordion title="Submission UUID">
    The long unique identifier used internally for a submission. It appears after `/submissions/` in the record's browser address and is required when creating a verification request.
  </Accordion>

  <Accordion title="UTC">
    Coordinated Universal Time, the standard time basis used by the app's date filters. A UTC date may differ from local time near midnight.
  </Accordion>
</AccordionGroup>

## Submission statuses

| Status | Meaning |
| --- | --- |
| **Draft** | Saved work that is still editable by its collector |
| **Submitted** | A finalized Enumerator record waiting for approval |
| **Approved** | A reviewed and accepted record, or a record finalized by an authorized higher role |
| **Verified** | An approved source assessment whose verification comparison has been confirmed |

<Warning>
  Finalized submissions are historical records and cannot be edited. If more fieldwork is needed, create a new submission.
</Warning>

## Configuration statuses

These statuses apply to client Projects, Project Types, tasks, and forms where relevant.

| Status | Meaning |
| --- | --- |
| **Draft** | An editable setup that is not active for fieldwork |
| **Published** | Active content available to the operational catalog when its related items are also published |
| **Inactive** | Temporarily unavailable; it may be reactivated |
| **Archived** | Retired configuration kept for history; only the Super Admin can archive |
| **Superseded** | An older published form version replaced by a newer active version |

## Workflow actions

<AccordionGroup>
  <Accordion title="Approve">
    Accept a finalized Enumerator submission after reviewing its answers and evidence. Approval is different from verification.
  </Accordion>

  <Accordion title="Archive">
    Retire a published or inactive client Project or Project Type while preserving its history. This action is reserved for the Super Admin.
  </Accordion>

  <Accordion title="Deactivate">
    Temporarily make an account or configuration unavailable without deleting its historical data.
  </Accordion>

  <Accordion title="Delete">
    Permanently remove an eligible account or configuration. Deletion may be blocked when operational history exists.
  </Accordion>

  <Accordion title="Export">
    Download matching records as an Excel or CSV file. Exports may contain sensitive field information and must be stored securely.
  </Accordion>

  <Accordion title="Finalize or submit">
    Complete a draft field record. The app validates required answers and evidence before making it final.
  </Accordion>

  <Accordion title="Publish">
    Make a valid form, task, Project Type, or client Project active for operational use.
  </Accordion>

  <Accordion title="Reactivate">
    Return an inactive account or configuration to active use.
  </Accordion>

  <Accordion title="Reinstate">
    Restore a previously removed assignment.
  </Accordion>

  <Accordion title="Remove or revoke an assignment">
    Stop future collection access while preserving existing submissions and assignment history.
  </Accordion>
</AccordionGroup>

## Verification terms

<AccordionGroup>
  <Accordion title="Network Assessment">
    The original assessment task whose approved submission can be used as the source of a verification comparison.
  </Accordion>

  <Accordion title="LV Network Assessment">
    The independent field assessment used to check an original Network Assessment.
  </Accordion>

  <Accordion title="Source submission">
    The approved or already verified Network Assessment being checked.
  </Accordion>

  <Accordion title="Verification submission">
    The finalized LV Network Assessment compared with the source submission.
  </Accordion>

  <Accordion title="Pending verification">
    A comparison request created but not yet confirmed by a reviewer.
  </Accordion>

  <Accordion title="Confirmed verification">
    A comparison that has been reviewed and completed. Confirmation changes the source submission to Verified.
  </Accordion>
</AccordionGroup>

## Safety and administration

<AccordionGroup>
  <Accordion title="Audit event">
    A historical record showing who performed an important administrative action and when it occurred.
  </Accordion>

  <Accordion title="Direct Supervisor">
    The Supervisor responsible for an Enumerator. SOS alerts from that Enumerator are sent to the direct Supervisor and active administrators.
  </Accordion>

  <Accordion title="SOS incident">
    An urgent safety alert containing the sender's location and optional description. It does not replace emergency services.
  </Accordion>

  <Accordion title="Slug">
    A stable, lowercase identifier made from letters, numbers, and hyphens. Slugs are used in web addresses and stored relationships.
  </Accordion>
</AccordionGroup>
